The Shift Has Already Happened

Agentic AI is not a roadmap item. It is live on GitHub today. The teams that understand how to use it are already shipping faster.

The Fundamental Shift

Assistive vs. Agentic AI

  • Assistive AI — responds when you ask. Copilot completions, inline chat, explain commands. Requires your full attention at every step.
  • Agentic AI — acts, reasons, plans, and iterates without requiring your hands on the keyboard for every step.
  • The mental model shift: you're not "prompting" anymore — you're "delegating."
  • "Your judgment is the scarce resource. Agentic AI frees it up."
  • GitHub's bet: agents that are repo-native, governed by your org's policies, and auditable at every step.
Demo 1

Side-by-Side: Assistive vs. Agentic

🤝 Assistive Mode

  • You write code, Copilot suggests completions
  • Inline chat: describe → see diff → accept/reject
  • Human in the loop at every step
  • Great for in-the-flow creative coding

🤖 Agentic Mode

  • You write a clear issue, assign it to Copilot, go do something else
  • Agent: observes → plans → acts → verifies → repeats
  • Human at the start (define) and end (review)
  • Returns a PR for you to review

"Agent-ready" tasks: bounded scope · measurable success · established tech stack · no ambiguous architectural decisions required

Understanding Agentic Surfaces

Agent Mode vs. Coding Agent vs. Agentic Workflows

IDE · Interactive
Copilot Agent Mode
Runs in VS Code / JetBrains. Multi-step, edits files, runs terminal commands. You stay in the loop in your IDE — iterative and conversational.
Cloud · Autonomous
Copilot Coding Agent
Runs in a cloud sandbox. Assign an issue to Copilot → it plans, codes, tests, and opens a PR. Fully autonomous — no IDE required.
CI/CD · Event-Driven
Agentic Workflows
GitHub Actions powered by AI. Triggered by repo events (issue closed, PR opened). Automated cascading actions — no human trigger needed.

Key insight: These are complementary surfaces, not competing tools. Agent Mode for interactive exploration, Coding Agent for delegated tasks, Agentic Workflows for automated pipelines.

Extending Copilot

Custom Agents

  • What they are: Specialized Copilot personas with custom instructions, tools, and domain knowledge — a security reviewer, a migration assistant, a docs writer
  • Defined as files that specify a name, description, instructions, and optionally MCP tools
  • Invoked by @agent-name in Copilot Chat — just like mentioning a teammate
Scope Where it lives Who can use it
Repository .github/agents/ directory Anyone working in that repo
Organization Org-level Copilot settings or shared config repo All members of the org
Enterprise Enterprise-level Copilot configuration All orgs and members across the enterprise

Pro tip: Start with a repo-level agent for your team's most common task. Promote to org-level once it's proven. Enterprise agents are ideal for cross-cutting concerns like security review or compliance checks.

Building & Customizing Coding Agents

Make the coding agent behave like a real member of your team using .github/copilot-instructions.md and well-structured issues.

# .github/copilot-instructions.md (TechMart)
## Stack
- Vanilla HTML/CSS/JS — no frameworks, no npm
- CSS custom properties for all theming values
## Conventions
- STUB_INFO stubs must remain as stubs — do not implement
- Issue bodies must include a ## Depends On section
  • Agent reads .github/copilot-instructions.md before every task
  • Session log = full audit trail: what it read, considered, and changed
  • Structured issues with acceptance criteria → dramatically better PRs
Customizing the Agent

Your Team's Contract with the Agent

  • Naming conventions — file names, function names, variable naming patterns
  • Preferred stack — "Vanilla HTML/CSS/JS only — no frameworks, no npm. CSS custom properties for theming."
  • What NOT to do — "STUB_INFO features are not implemented; never replace stubs with real API calls."
  • Issue format — "Every issue body must include a ## Depends On section so the agentic workflow can trace the dependency graph."
  • Demo exceptions — "Some files intentionally violate conventions for demo purposes. Don't refactor them."
  • Think of it as an always-up-to-date onboarding doc that also governs your AI agents

Model Context Protocol (MCP)

An open standard for connecting AI agents to external tools and data sources — think of it as the USB-C port for AI.

Model Context Protocol

Connecting Agents to Enterprise Systems

  • MCP servers expose "tools" (actions: run query, create ticket) and "resources" (data: DB schema, API specs)
  • JSON-RPC based — any developer can build an MCP server in a few hours
  • Open protocol (broadly adopted) — your MCP servers work with any compliant AI client

Enterprise Governance

Full AI power + full enterprise control. You don't have to choose between the two.

Control What it does
Feature toggles Enable/disable coding agent, code review, Autofix per org or repo
Model selection Pin orgs to specific models (GPT-4o, Claude) for compliance
IP protection "Exclude from training" — org code never used to train foundation models
Content exclusions Block Copilot from accessing secrets files or regulated data paths
Audit logs Every Copilot code change is logged — who triggered it, what was accepted
Seat management Granular access control, tier management, usage analytics
